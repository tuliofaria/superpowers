# PR Watch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When the `watchPr` project-config key is true, have `finishing-a-development-branch` keep watching the PR it opened until checks and reviews settle.

**Architecture:** Add a new procedure file
`skills/finishing-a-development-branch/pr-watch.md`. It is the loop plus
the known-reviewers table, and is called from finishing's Option 2 in the
same way as `cross-provider-review.md`. The config key is documented in
`project-config.md` and asked by `/sp-init`. The tests are grep-based
structure checks in the existing test script.

**Tech Stack:** Markdown skill text, the `gh` CLI (REST and GraphQL), and
bash test assertions.

**Spec:** `docs/superpowers/specs/2026-10-08-pr-watch-design.md`

## Global Constraints

- Fork only. No upstream PR.
- Skill text is in English, in the voice of `cross-provider-review.md`:
  imperative, short sections, "your human partner".
- `watchPr: true | false`, default `false`.
- Authorized without asking:
  - push fix commits (normal push only, never a force-push);
  - reply to threads;
  - comment `@coderabbitai review`;
  - run `gh run rerun <id> --failed` once per run;
  - edit the PR body once at the end.
- Never: merge, close, approve, resolve threads, or tick "Run on-demand
  review".
- Budget: 3 fix rounds (a CI fix counts as a round) and 2 CodeRabbit
  re-triggers.
- Waits: reviewers are polled every 2 minutes, up to 20 minutes per wait.
  For a rate limit, wait until `updated_at` + N minutes + 1 minute.
- GitHub only. If `gh auth status` fails or the forge is not GitHub, say
  so in one line and skip the watch.

## Review Focus

- A rate-limit block left over from an older commit (`headCommitId` is
  not HEAD) must not be read as "CodeRabbit is limited now" → Task 2
  asserts `headCommitId`.
- Grok posts from the PR author's account: a Grok comment must never
  count as our answer to a thread → Task 2 asserts the "does not end with
  `by Grok PR Reviewer`" rule.
- CodeRabbit stuck in "reviewing" must end in a report, not an endless
  wait → Task 2 asserts `20 minutes`.
- A fix round whose local suite is red must not push → Task 2 asserts
  `no push on a red suite`.
- A PR body that already has a `## PR watch` section gets that section
  replaced, and the rest of the body is untouched → Task 2 asserts
  `leave the rest of the body untouched`.

- [ ] **Step 3: Write `pr-watch.md`.** Transcribe spec Component 1 into
  procedure voice, using these sections in order:
  1. Intro paragraph: called by finishing when `watchPr: true`; input is
     the PR number and `<base-branch>`. Also state the standing
     authorization (the allowed and never-allowed lists from Global
     Constraints, including "never force-push").
  2. `## Before you start`: the forge check (`gh auth status`, GitHub
     only).
  3. `## Reading the PR`: the four commands from the spec.
  4. `## Known reviewers`: the spec's table, plus the CodeRabbit state
     markers written out verbatim from "Observed reviewer behavior" (the
     two HTML markers, "Currently processing new changes", "Or wait N
     minutes", `headCommitId`, the `recent_review_start` / "No actionable
     comments" section, and the reviewed SHA in "📥 Commits").
  5. `## Answered threads`: the "Answered" rule.
  6. `## The loop`: WAIT / EVALUATE / STOP? / ACT, the three stop
     conditions, the ACT priority order, the budget wording "at most 3
     rounds" and "2 re-triggers", waiting (`gh pr checks <n> --watch`,
     polling every 2 minutes for up to 20 minutes, background `sleep`),
     and "no push on a red suite".
  7. `## Report`: the template, "none" for empty lists, written once
     with `gh pr edit <n> --body-file`, replacing an existing
     `## PR watch` section and "leave the rest of the body untouched".
     State that the worktree stays.

  Keep it under about 200 lines. Do not copy the observation timings
  (9 seconds, 4.5 minutes); they belong in the spec, not the procedure.
